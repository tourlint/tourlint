## 5. TP-04 실패 — 부분 검수 50% 경계

정상 8곳 상품에 조회 실패를 주입한다. **존재하지 않는 `contentid`를 쓰지 않는다** — 공사 API는 없는 ID에 0건 정상 응답을 주므로(EX-EI-004) 조회 실패와 경로가 다르다.

### TP-04a — 4/8 실패 (50%, 초과 아님)

실패 주입: `129784` `1756581` `2868869` `125769`

```
확인 불가 4건 (KTO_FETCH_FAILED · 콘텐츠 단위 격리)
차단 0 · 오류 0 · 주의 0 · 확인 불가 4
점수 = 100 − (4×3) = 88점    ← 점수를 산출해야 한다
```

검증 포인트: 나머지 4곳이 **정상 판정된다**(EX-CM 원칙 ① 부분 성공). 실패한 4곳은 삭제되지 않고 확인 불가로 결과에 남는다(EX-CM-003).

### TP-04b — 5/8 실패 (62.5%, 초과)

실패 주입: 위 4건 + `3022373`

```
AUDIT_PARTIAL 승격 → 점수 미산출
화면: 「부분 검수」 배지 + 실패 콘텐츠 5곳 표기
숫자 점수 노출 금지 (UI-S3-006 · FR-AU-007)
```

⚠️ **`AUDIT_PARTIAL`은 '상품' 단위 예외 사유코드**이며 등급 4종에 들어가지 않는다. finding 목록에는 실패한 5곳이 각각 확인 불가로 남되, **점수만 산출하지 않는다.**

## 6. 이 표를 만들며 발견한 것 — 명세 보완 2건 (✅ 모두 반영 완료)

### ⑧ R04 임계치 3곳은 2박 3일 상품에서 사실상 항상 발동한다 — ✅ 반영 완료

2박 3일이면 식사만 최소 3회다. `contentTypeId` 39가 자동으로 3곳이 되어 **모든 정상 상품에 주의 1건이 붙는다.** TP-01이 92점이 되는 이유가 이것이며, 실제로는 아무 문제 없는 일정이다.

**권장 조치 (택1 또는 병행)**

| 안 | 내용 | 영향 |
|---|---|---|
| A | 일정 항목 유형이 **식사·숙박·휴식·이동·자유시간**인 항목을 R04 집계에서 제외 | R04를 "관광 콘텐츠 편중" 규칙으로 정확히 한정. 권장 |
| B | 임계치를 **일차 단위 3곳 / 상품 전체 5곳**으로 분리 | 12곳 상품의 과탐 완화 |

→ ✅ **A안 채택.** FR-RU-040이 기능 요구사항 v1.6(2026-08-20)에서 개정되어 집계 대상이 일정 항목 유형 `관광`으로 한정됐다. 이에 따라 TP-01 기대값은 주의 1건 · **96점**으로 확정(§2).

### ⑨ 존재하지 않는 `contentid`의 상세 조회 응답 처리가 미정의 — ✅ 반영 완료

공사 API는 없는 ID에 `resultCode 0000` + `items` 빈 문자열을 반환한다(EX-EI-004에 따르면 **정상 응답**). 그런데 상세 조회가 0건이면 판정 근거가 없다. 현행 사유코드 어디에도 이 상황이 없다 — `KTO_FETCH_FAILED`(조회 실패)도 `CONTENT_HIDDEN`(showflag 0)도 아니다.

→ ✅ 예외 사유코드 **`CONTENT_NOT_FOUND`**(콘텐츠 단위 · 확인 불가)가 예외처리 요구사항 v1.3(2026-08-20)에 신설됐다(EX-EI-010). 예외 사유코드 38종 → 39종. 재시도하지 않으며 `KTO_FETCH_FAILED`(조회 실패) · `CONTENT_HIDDEN`(비표출 · 차단)과 구분한다.

→ 이 때문에 TP-04를 "없는 ID" 대신 "조사 실패 주입"으로 설계했다.
