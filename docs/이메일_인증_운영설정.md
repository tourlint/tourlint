# 신규 가입 이메일 인증 운영 설정

2026.09.18 · #539 · Gmail + Google Apps Script

현재 사이트 주소 `https://tourlint-web.up.railway.app`을 유지하고, 소유한 Gmail 계정으로 인증메일을 보낸다. 도메인 구매나 유료 메일 서비스 가입은 필요하지 않다. Google Apps Script 개인 계정의 공식 한도는 현재 하루 수신자 합계 100회이며, 같은 사람에게 재전송해도 한도를 쓴다. 한도는 사용자별로 첫 요청 후 24시간에 재설정되며 다른 스크립트와 공유될 수 있다. 이 구성은 소량 발송용이며 한도 초과·Google 장애 시 신규 가입을 진행할 수 없다. 기존 계정 및 심사용 계정 로그인은 그대로 유지한다.

## 1. Gmail 계정 준비

발신용으로 쓸 Gmail 계정으로 [Google Apps Script](https://script.google.com/home)에 로그인한다. 새 계정을 꼭 만들 필요는 없지만 서비스용 계정을 쓰면 개인 메일과 구분하기 쉽다. 받는 사람에게 발신자의 Gmail 주소가 보인다. 가입자는 Gmail뿐 아니라 다른 이메일도 사용할 수 있고, Google 로그인이나 권한 승인을 요구받지 않는다.

## 2. 스크립트 붙여 넣기

1. **새 프로젝트**를 누르고 이름을 `TourLint 인증메일`로 바꾼다.
2. 기본 `Code.gs` 내용을 지운 뒤 저장소의 [`scripts/signup-mail/Code.gs`](../scripts/signup-mail/Code.gs) 전체 내용을 붙여 넣는다.
3. 저장한다. 이 파일은 인증메일 한 종류만 보내며 Gmail 메일함을 읽는 기능은 없다.

## 3. 연결용 비밀값 저장

이 값은 Gmail 비밀번호가 아니라 **TourLint 서버가 보낸 요청임을 확인하는 별도의 난수**다. 코드 본문·GitHub·채팅에 넣지 않는다.

- 이번 작업에서 생성한 로컬 파일: `outputs/signup-verification/apps-script-mail-secret.txt`. Git 추적 대상에서 제외되어 있다. 한 줄 전체를 복사한다.
- 새 환경에서는 터미널의 `openssl rand -hex 32`로 새 값을 만들 수 있다. 동일한 값을 두 곳에 넣어야 한다.

Apps Script 왼쪽 **프로젝트 설정(톱니바퀴) → 스크립트 속성 → 스크립트 속성 추가**에서 다음을 저장한다.

| 속성 | 값 |
|---|---|
| `AUTH_MAIL_SECRET` | 위에서 복사한 64자리 비밀값 |

## 4. 메일 발송 권한 승인

1. 코드 편집기로 돌아간다.
2. 상단 함수 선택에서 **`authorizeMail`**을 선택하고 **실행**을 누른다.
3. Google의 권한 확인 화면에서 발신에 사용할 본인 계정을 확인하고 메일 발송 권한을 승인한다. 계정 로그인과 권한 승인은 계정 소유자가 진행한다.
4. `authorizeMail`은 권한과 잔여 한도만 확인하며 실제 메일을 보내지 않는다. `doPost`를 수동 실행할 필요는 없다.

## 5. 웹 앱 배포

1. 오른쪽 위 **배포 → 새 배포**를 누른다.
2. 유형 선택에서 **웹 앱**을 선택한다.
3. **실행 사용자: 나**, **액세스 권한: 모든 사용자/누구나**로 설정한다.
4. **배포**를 누르고 표시된 웹 앱 URL을 복사한다. 주소 끝이 `/exec`여야 한다. `/dev` 테스트 주소는 사용하지 않는다.

외부에서 접근 가능하게 하는 이유는 Railway 서버가 Google 로그인 없이 호출해야 하기 때문이다. 메일 발송은 별도로 HMAC 서명·요청 시각·요청 ID를 검증한다. 비밀값을 모르는 요청은 메일을 발송하지 못한다. URL에 비밀값이나 인증코드를 붙이지 않는다.

스크립트를 나중에 수정하면 **배포 관리 → 수정 → 새 버전**을 배포해야 기존 `/exec` 주소에 반영된다. 저장만으로는 운영 배포가 갱신되지 않는다.

## 6. Railway 연결

Railway → TourLint → production → **api 서비스 → Variables**에 다음 값을 저장한다.

| 변수 | 값 |
|---|---|
| `AUTH_MAIL_SCRIPT_URL` | 복사한 `https://script.google.com/macros/s/…/exec` 주소 |
| `AUTH_MAIL_SECRET` | Apps Script 속성에 저장한 것과 정확히 같은 64자리 값 |

web 서비스나 `NEXT_PUBLIC_` 변수에 넣지 않는다. 적용/배포 버튼이 표시되면 변경을 적용한다.

기존 `RESEND_API_KEY`, `AUTH_EMAIL_FROM`은 이 방식에서 사용하지 않는다. 이번 기능의 Resend 버전은 운영에 배포되지 않았으므로 제거해도 기존 사이트에는 영향이 없다. Resend도 더 사용하지 않을 경우 Resend 대시보드에서 해당 API 키를 폐기할 수 있다. 다른 프로젝트와 공유하는 키는 먼저 사용처를 확인한다.

## 7. 코드 배포와 실제 수신 확인

1. 위 설정을 완료한다.
2. 운영 DB에 `db/migrations/2026-09-18_signup_verification.sql`을 적용한다. 기존 데이터는 변경하지 않고 두 테이블만 추가한다.
3. CI가 통과한 기능 PR을 dev에 머지하고 별도 release PR로 main에 반영한다.
4. `/health`의 배포 커밋, `checks.signupEmail: ok`, `checks.schema: ok`를 확인한다. `signupEmail`은 URL·비밀값의 설정 형식만 확인한다. 실제 Google 권한·메일 도달 여부를 보증하지 않는다.
5. 운영 회원가입 화면에서 소유한 수신 이메일로 코드를 요청해 실제 메일을 확인하고 가입·로그인·로그아웃을 점검한다. 실제 수신 확인 전에는 운영 완료로 판정하지 않는다.
6. 기존 심사용 계정의 로그인과 준비된 상품이 그대로인지 확인한다.

## 동작과 제한

- 코드 유효기간 10분, 코드당 오입력 5회. 재전송 시 이전 코드는 무효다.
- 재전송 간격 60초, 이메일당 시간당 5회. 서비스 전체 분당 10회·UTC 날짜당 100회. DB 한도와 Google의 24시간 한도는 별개이며 둘 다 통과해야 발송한다. 발송 실패도 서버 요청 한도에 포함한다.
- 코드 원문은 메일 외에 DB·응답·실행 로그에 남기지 않는다. 가입 DB에는 scrypt 해시를 둔다.
- 이메일에 연결된 UUID와 코드가 모두 맞아야 가입 가능하다. 계정 생성과 코드 소비는 하나의 트랜잭션이며 동시 요청도 한 번만 소비한다.
- Apps Script 요청은 HMAC-SHA256으로 서명하며 120초 이내 요청만 허용한다. 고정 템플릿·단일 수신자만 지원한다. 서버 비밀값은 HTTP 본문에도 보내지 않는다.
- 스크립트 잠금과 처리 이력으로 같은 요청의 중복 발송을 막는다. 결과가 불명확한 요청은 재발송하지 않는다. 처리 이력에는 이메일·코드 원문 대신 지문·상태·만료 시각만 저장한다. 이력은 15분 후 만료되고 다음 유효 요청 때 정리된다.
- 메일 전송 중 가입 DB 잠금은 잡지 않는다. 발송 실패 시 해당 코드를 무효화한다. 응답 본문에서 발송 성공과 동일 요청 ID가 확인돼야 코드를 활성화한다.
- 마지막 발송이 24시간 지난 가입 인증 행과 만료 전역 한도를 매시간 정리한다. IP 등 추가 개인정보는 저장하지 않는다.
- 기존 계정에도 동일한 인증메일 요청 응답을 제공하지만, 중복 가입으로 비밀번호를 바꾸거나 로그인 세션을 발급하지 않는다.
- 비밀번호 재설정·소셜 로그인은 이번 변경에 포함하지 않는다.
