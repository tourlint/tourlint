# TourLint 운영정보 파싱 규칙 — 구현 지침

| 항목 | 내용 |
|---|---|
| 작성일 | 2026-08-20 |
| 근거 | 필드 대조표 확정본(실측 발견 7건) · FR-AU-004 ~ 016 · EX-PS-001 ~ 010 |
| 대상 | `apps/api/src/engine` 운영정보 해석기 (A트랙) |
| 원칙 | **모르면 모른다고 말한다.** 판별 불가 시 첫 값을 단정하지 말고 확인 불가로 넘긴다 |

## 1. 전처리 — 조각 경계

원문을 조각(fragment)으로 자를 때 **아래 문자열을 모두 경계로 취급**한다.

```
/    ,    ·    ,    <br>    <br/>    <BR>    <br />
```

⚠️ `<br>`는 실측에서 확인된 실제 데이터다 — 강릉 동부시장 `06:00~23:00<br>※ 점포별 상이함`, 감자적본부 `- 10:00~20:30<br>- 준비시간 14:30~15:00<br>- 마지막 주문 19:45`.

**지문(fingerprint)은 전처리 전 원문으로 생성한다** (DR-FP-004 · FR-AU-016). 전처리는 해석 입력에만 적용한다.

## 2. 라벨 블록 분리 — 줄바꿈이 없다

실측 원문에는 개행이 없고 라벨 블록이 그대로 이어 붙는다.

```
[월요일]- 07:40~16:00- 마지막 주문 15:45[수요일~일요일]- 07:40~19:30- 준비시간 15:30~17:00- 마지막 주문 19:15
```

**분리 규칙**

1. `[...]` 대괄호 블록을 요일 라벨 경계로 인식하고 그 앞에서 자른다
2. 선행 기호 `- `, `※`, `•`, 전각 공백을 제거한다
3. 남은 조각을 아래 라벨 사전으로 분류한다

| 라벨 | 매핑 필드 |
|---|---|
| 운영시간 · 이용시간 · 관람시간 · 영업시간 | `openHours` |
| 매표시간 · 입장마감 · 마지막 주문 · 라스트오더 | `admissionCutoff` |
| 준비시간 · 브레이크타임 · 휴게시간 | `breakTime` |
| 입실 · 체크인 | `checkIn` |
| 퇴실 · 체크아웃 | `checkOut` |
| 하절기 · 동절기 · N월~N월 | `seasonalHours` |

**라벨이 없는 시각 범위가 둘 이상이면 첫 범위를 운영시간으로 단정하지 않는다.** `PARSE_CONDITIONAL`로 확인 불가 처리한다 (EX-PS-007 · FR-AU-014).

## 3. 입실/퇴실 패턴 — 운영시간으로 읽으면 안 된다 🔴

레포츠(28)와 숙박(32)에서 확인된 패턴:

```
usetimeleports = "- 입실 15:00- 퇴실 11:00"
```

이걸 `openHours = 15:00~11:00` 으로 읽으면 **심야 영업으로 오판**하고, 그 결과 낮 시간대 방문이 전부 `OPEN_HOUR_CONFLICT` 차단이 된다.

**판별 규칙** — 조각에 `입실`·`체크인`·`퇴실`·`체크아웃` 토큰이 있으면 `openHours`가 아니라 `checkIn`/`checkOut`으로 매핑하고, **R01 운영시간 판정에서 제외**한다.

숙박(32)은 별도로 FR-AU-011에 따라 R01 휴무 판정 대상에서도 제외된다.

## 4. 문의처 — 기관명과 전화번호가 섞인다

```
infocentershopping = "㈜강릉농산물도매시장 관리소 033-646-4654"
infocenter         = "경포여행자센터 033-640-4531"
infocenterculture  = "033-660-3301~8"
```

**추출 규칙**

1. 전화번호 정규식으로 번호부를 추출: `0\d{1,2}[-.]?\d{3,4}[-.]?\d{4}` (`0507`·`010` 포함)
2. `033-660-3301~8` 형태의 **범위 표기**는 첫 번호까지만 취해 `033-660-3301`로 정규화하고, 원문은 그대로 보존한다
3. 번호 앞의 문자열은 `contactName`으로 분리 보존한다 (확인 필요 목록에 함께 노출)
4. 번호를 찾지 못하면 `contactTel = null`, 확인 필요 목록에는 `정보 없음` 표시 (EX-PS-010)

## 5. 화면 출력 — `<br>` 이스케이프 후 복원

원문 그대로 표시(UI-S3-012)와 이스케이프(NF-SC-005)를 동시에 지키면 화면에 `&lt;br&gt;`가 노출된다.

**순서를 지킨다**

```
1) HTML 이스케이프를 먼저 적용한다
2) 그 결과에서 &lt;br&gt; · &lt;br/&gt; 토큰만 <br> 로 되돌린다
3) 그 외 태그는 절대 복원하지 않는다
```

허용 토큰은 `br` 하나뿐이다. 화이트리스트를 늘리지 않는다.

## 6. 조건부 · 참조형 — 확인 불가로 명시

| 원문 | 판정 | 사유코드 |
|---|---|---|
| `예약시 운영` | 확인 불가 | `PARSE_REFERENCE` |
| `점포별 상이함` | 확인 불가 | `PARSE_TARGET_VARIES` |
| `홈페이지 참조` · `문의 요망` | 확인 불가 | `PARSE_REFERENCE` |
| 빈 문자열 | 확인 불가 | `PARSE_MISSING` |
| `월요일이 공휴일인 경우 익일 휴관` | 추정(`ESTIMATED`) | — (R01 차단 → 주의 강등) |
| `연중무휴(1월 1일/설날/추석 당일은 …휴관)` | `alwaysOpen` + `partialClosed`, 신뢰도 `ESTIMATED` | DR-NM-011 |

`alwaysOpen`과 구체적 휴무가 함께 나오면 예외가 아니라 **병합 규칙 적용 대상**이다. 전체 휴관이면 `alwaysOpen`을 내리고, 일부 휴관이면 유지한 채 `partialClosed`에 담되 **두 경우 모두 신뢰도를 `ESTIMATED`로 낮춘다.**

## 7. 골든 케이스 — 파서 변경 시 반드시 통과해야 하는 3건

이 3건이 깨지면 파서 변경을 되돌린다.

### ① 감자유원지 (2941250) — 한 필드에 4개 정보

```
- 11:00~20:00- 준비시간 15:30~17:00- 점심 마지막 주문 15:00 / 저녁 마지막 주문 19:30
```

기대 산출:
```json
{ "openHours": [{"from":"11:00","to":"20:00"}],
  "breakTime": [{"from":"15:30","to":"17:00"}],
  "admissionCutoff": [{"label":"점심","at":"15:00"},{"label":"저녁","at":"19:30"}],
  "confidence": "CONFIRMED" }
```

### ② 오죽헌·시립박물관 (129784) — 라벨 병기

```
매표시간 09:00~17:00 관람시간 09:00~18:00
```

기대 산출: `openHours 09:00~18:00` · `admissionCutoff 17:00` · 신뢰도 `CONFIRMED`
휴무 원문은 `alwaysOpen=true` + `partialClosed` + 신뢰도 `ESTIMATED`

### ③ 금진리321카라반 (2792194) — 입실/퇴실

```
- 입실 15:00- 퇴실 11:00
```

기대 산출: `checkIn 15:00` · `checkOut 11:00` · `openHours` **없음** · R01 운영시간 판정 제외
