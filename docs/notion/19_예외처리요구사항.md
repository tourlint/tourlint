## 3. 예외 분류 체계
```plain text
        영향 범위                     처리 방식
  ┌───────────────────┐        ┌────────────────────────┐
  │ 조각 (fragment)   │  ───→  │ unparsed 기록 · 해당 필드만 확인 불가
  │ 구간 (segment)    │  ───→  │ 해당 구간만 확인 불가 (R08) · 타 구간 정상 판정
  │ 콘텐츠 (content)  │  ───→  │ 해당 콘텐츠만 확인 불가 · 나머지 정상 판정
  │ 규칙 (rule)       │  ───→  │ 해당 규칙만 확인 불가 · 타 규칙 정상 수행
  │ 일정 항목 (item)  │  ───→  │ 항목 유지 + 검수 제외 배지 · 감점 없음
  │ 상품 (product)    │  ───→  │ 부분 검수 표시 · 점수 미산출
  │ 요청 (request)    │  ───→  │ 거부 + 사유 안내 · 데이터 변경 없음
  │ 배치 (batch)      │  ───→  │ 실패 기록 · last_covered 미갱신 · 다음 회차 복구
  └───────────────────┘        └────────────────────────┘

원칙: 위에서 아래로 갈수록 영향이 크다.
      예외는 가능한 한 위쪽 단위로 격리하고, 아래로 확대하지 않는다.
```

<td>예외는 발생 지점에서 가장 작은 단위로 격리해야 하며, 상위 단위로 승격하는 조건을 명시적으로 정의한 경우에만 확대할 수 있다.</td>

## 16. 예외 시나리오 테스트 목록 (W7 전수 확인)
- [ ] 공사 인증키를 잘못된 값으로 바꾸면 `KTO_AUTH_ERROR`로 즉시 중단되고 재시도가 발생하지 않는다
- [ ] 응답을 XML 오류로 강제하면 JSON 파싱 오류가 아니라 인증 · 쿼터 오류로 분류된다
- [ ] 8곳 중 2곳 조회를 강제 실패시키면 6곳이 정상 판정되고 2곳만 확인 불가로 표시된다
- [ ] 8곳 중 5곳 실패 시 점수가 표시되지 않고 `부분 검수` 배지가 나타난다
- [ ] LLM 엔드포인트를 차단해도 검수가 끝까지 완료된다
- [ ] 지도 API를 차단해도 R08만 확인 불가가 되고 나머지 규칙은 판정된다
- [ ] 기상 예보 API를 차단하면 평년 기준 판정으로 강등되고 화면 표기가 바뀐다
- [ ] 이동수단을 대중교통으로 바꾸면 R08이 호출 없이 확인 불가로 처리된다
- [ ] 차단 finding에 무시 API를 직접 호출하면 거부된다
- [ ] 차단이 있는 상태에서 출시 승인 API를 직접 호출하면 거부된다
- [ ] 타 계정 리소스 ID로 조회하면 404 계열이 반환되고 존재 여부가 드러나지 않는다
- [ ] 충돌하는 수정안 2건을 선택하면 확정이 막히고 충돌 쌍이 표시된다
- [ ] 되돌리기를 두 번 연속 요청하면 두 번째가 거부된다
- [ ] 예산을 10건으로 낮추고 8건 소진 시 배치가 자동 중지된다
- [ ] 배치를 3일 중단 후 재개하면 누락된 3일치가 순회 조회된다
- [ ] 평일 배치 결과가 0건이면 `last_covered`가 갱신되지 않는다
- [ ] 비표출 전환된 콘텐츠의 명칭 · 주소 · 이미지가 화면 · API · PDF 어디에도 나타나지 않는다
- [ ] 검수 진행 중 화면을 이탈했다 재진입하면 진행률이 이어진다
- [ ] 잘못된 양식 파일을 올리면 오류 행 번호가 표시되고 서비스가 중단되지 않는다
- [ ] 골든 케이스 3건이 스키마 · 파서 변경 후에도 동일 결과를 낸다
