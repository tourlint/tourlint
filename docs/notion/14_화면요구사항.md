	화면 9개의 구성 요소와 정보 구조를 정의한다. 이 문서의 기준은 미관이 아니라 **"판정 근거가 화면에서 검증 가능한가"** 다.

</callout>

### 상품 작업 진입점 (2026.09.18 개편)
- 홈·기획·검수 카드와 목록에 단계에 맞는 명시적 링크(기획 이어하기 / 검수 결과 보기)를 제공한다. 상품명 링크도 유지한다. **기획 중 상품은 편집 화면으로 연다** — 저장한 값이 채워진 등록 화면과 같은 2단이라 이어서 채울 수 있다. 저장하면 장소 확정 화면으로 간다.
- 카드와 목록의 삭제 버튼은 탐색 링크와 분리한다. 상품명을 표시하는 확인 창에서 일정·검수 기록이 함께 삭제되고 복구할 수 없음을 알린다. 취소는 아무 요청도 보내지 않으며, 확정 후 기존 DELETE API 성공 시 목록과 집계에서 해당 상품만 제거한다. 실패 시 창에서 오류와 재시도를 제공한다. 요청 중 중복 실행을 막는다.

## 6. 화면 3 · 검수 결과 (진단) (UI-S3)
<callout icon="🩺" color="yellow_bg">
	**이 화면에서 일정은 절대 바뀌지 않는다.** 버튼 라벨은 "적용"이 아니라 **선택**이어야 하며, 선택은 패치 화면의 확정 전까지 일정 데이터에 영향을 주지 않는다. 이 원칙이 화면 설계의 최우선 제약이다.
</callout>
### 검수 결과 정보 구조 (2026.09.18 개편)
- 상품명과 출발 정보, 일정 편집·재검수 진입점을 상단에 둔다. 출시 준비도·출시 가능 여부와 등급별 건수는 서버 값을 그대로 사용한다.
- 요약 아래에 문제와 수정안 / 직접 확인할 곳 / 출시·리포트 바로 가기를 제공한다. 직접 확인 수는 별도 확인 목록의 개수다. 출시 가능 여부와 확인 목록은 서로 대체하지 않는다.
- 발견 항목은 차단 → 오류 → 주의 → 확인 불가 순이며 무시한 항목은 뒤에 둔다. 전체·등급·무시 필터를 제공하고 필터 변경으로 선택한 수정안을 잃지 않는다. 건수는 각 필터의 실제 항목 수를 사용한다.
- 수정안은 선택 → 전후 미리보기 → 확정하고 재검수 순서다. 선택 자체는 일정을 바꾸지 않는다. 미리보기 생성 시 해당 영역으로 이동하고, 충돌·오래된 미리보기·되돌리기 등 기존 보호를 유지한다.
- 직접 확인 섹션은 문의 내용 생성과 항목별 확인을 유지하며 확인 표시 자체는 점수를 바꾸지 않음을 명시한다. 출시·리포트 영역은 차단/부분 검수 등 기존 제한을 유지하며 이용 불가 이유도 표시한다.
- 판정 근거와 조회 기준·감점 계산은 읽을 수 있게 유지한다. 모바일에서는 요약과 도구를 세로로 배치한다.
