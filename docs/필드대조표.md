## 3. 발견 사항

### A. ➕ searchKeyword2가 좌표·수정일자·분류체계를 이미 반환한다

문서 호출량 산정은 "키워드 검색 8 + 공통정보 8(좌표·수정일자) + 소개정보 8"인데, **키워드 검색 응답에 이미 `mapx` · `mapy` · `modifiedtime` · `cpyrhtDivCd` · `lclsSystm1/2/3`가 들어 있다.**

- 다만 `homepage` · `overview`는 공통정보에만 있고, R06 지문은 소개정보 필드 기반이므로 **완전 대체는 불가**
- 신규 매칭 건에 한해 공통정보 호출을 생략할 여지가 있어 호출량 최적화 후보로만 기록. **W1 구현 시 성능이 목표를 못 맞출 때 꺼내 쓰는 카드**로 두고, 지금 명세를 바꾸지는 않는다(계약 단순성 우선)

### B. ➕ detailIntro2(문화시설)에 `spendtime`이 있다 ★

11번 응답 필드에 `spendtime`(소요시간)이 존재한다. 문서는 "반복정보 조회(detailInfo2)에 소요시간이 없어 **기본 체류시간 테이블(G-046 · FR-IN-011)로 대체**한다"고 확정했는데, **소개정보에는 유형에 따라 있을 수 있다.**

- 관광지(12) · 음식점(39) 응답에는 없음 → 유형별 편차
- **값이 실제로 채워져 있는지 확인 필요**(필드만 있고 빈 문자열일 가능성)
- 채워져 있다면: 문화시설에 한해 `spendtime` 우선 사용 → `기본값 적용` 배지가 줄고 R03 시간 판정 정확도가 올라감. 명세 개정 대상(FR-IN-011 · G-046)
- 비어 있다면: 현행 유지, 대조표에 기록만

### C. 구 코드체계 값 공백 여부

G-058은 "구 코드는 상세 조회에서만 빈 값, 목록 조회에서는 채워져 반환"이라고 서술한다. 필드 존재는 확인했으므로 **값**만 확인하면 서술이 확정된다.
